Example Codebase Overview

Two-package repository: Julia data generation writes Zarr datasets; Python reads Zarr datasets and trains/evaluates configurable graph neural networks.

Class diagram

Class/struct descriptions

Python core

  • Configurable: ABC requiring from_config.
  • ConfigHandler / PyObjectTag: YAML tags, references, sweeps, random/range expansion.
  • GNNModel: configurable model assembly with encoder, pooling/latent path, optional graph features, downstream task heads.
  • ModuleWrapper: adapts callables for ModuleList.
  • Snapshot: dataclass for checkpoint state.
  • Trainer / TrainerDDP: full training, resume, validation/test, DDP orchestration.

Python model components

  • GNNBlock: graph convolution, normalization, activation, optional residual/dropout.
  • SkipConnection: identity or linear residual projection.
  • Sequential: config wrapper around PyG Sequential with optional outer skip.
  • LinearSequential: dense MLP-like head.
  • RedrawProjection, GPSModel, GPSTransformer: GPS graph transformer stack with performer projection redraw support.

Python data/evaluation

  • ExampleDatasetBase: file validation, metadata, chunk processing for Zarr-backed data.
  • ExampleDataset: PyG dataset mapping global indices to Zarr files or processed tensors.
  • DataLoaderFactory: constructs datasets/splits/loaders from shared or stage-local config.
  • DistributedDataLoaderFactory: distributed samplers for DDP.
  • Evaluator, Tester, Validator: collect task losses/metrics into data frames and reports.
  • DefaultEarlyStopping: metric patience/grace-period stopping with any/all aggregation.

Julia generation structs

  • CsetFactory: top-level callable dispatcher over configured cset makers.
  • Maker structs: Polynomial, Layered, Random, Destroyed, Grid-like, ComplexTop, and Merged makers; validate JSON schemas and return csets plus metadata.
  • FlipParamDeterminer: helper for connectivity-targeted random causets.
  • BranchedManifoldCauset: custom causet type integrated with CausalSets methods.

Module diagram

Module descriptions

Python package ExamplePy/src/Example

  • config_utils.py, utils.py: YAML tags, config sweeps, import/path helpers, seeding.
  • dataset_base.py, dataset_ondisk.py, load_zarr.py: Zarr loading, metadata, PyG data conversion.
  • dataloaders.py: stage-aware dataset splitting and PyG/Distributed loaders.
  • gnn_model.py, models/*: configurable GNN model and component library.
  • evaluate.py, early_stopping.py, train.py, train_ddp.py: metrics, stopping, checkpoint/resume, train/test, DDP.
  • ExampleTune/tune.py: Optuna integration for YAML sweep/range/random tags.

Julia package Example.jl/src

  • Example.jl: package module, includes/exports API.
  • csetgeneration*.jl, layeredgeneration.jl, branchedcsetgeneration.jl, grid_like_causets.jl: causal-set generation variants.
  • csetmerging.jl, destroy_manifold_like_cset.jl: combine or perturb generated csets.
  • graph_utils.jl, curvature_on_manifold.jl, utils.jl: graph algorithms, curvature helpers, config validation.
  • cset_factories.jl: schema-validated functor factory layer.
  • preparation.jl, save_data.jl: distributed production and Zarr persistence.

How to run tests / main entry points

Python

  • Install: cd ExamplePy && pip install -r requirements-cpu.txt (or CUDA/ROCm/macOS variant), then pip install -e .[dev,docs].
  • Tests: pytest; targeted example: pytest test/test_trainer.py.
  • Main training flow: load config with Example.config_utils.get_loader(), build loaders with DataLoaderFactory.from_config(...).prepare_dataloaders(), create Trainer.from_config(...), call run_training and run_test.
  • Example configs: ExamplePy/configs/train_classifier.yaml, train_custom_model.yaml, train_ddp.yaml.

Julia

  • Tests: julia --project=Example.jl -e "using Pkg; Pkg.test()" or REPL using TestItemRunner; @run_package_tests.
  • Main data generation: add workers with Distributed.addprocs(n), define make_data(factory::CsetFactory)::Dict, then call Example.produce_data(chunksize, configpath, make_data; zip=false).
  • Example configs: Example.jl/configs/createdata_default.yaml, Example.jl/examples/example_config.yaml.

Constraints, risks, and open questions

  • Architecture preference in AGENTS.md: keep hot paths branch-light; resolve variation during config/construction.
  • !pyobject config tags need full import paths; short aliases such as tgnn.SAGEConv are expected to fail.
  • GNNModel enforces mutual exclusivity between pooling and latent model paths; graph-feature network and aggregation must be configured together.
  • GNNModel infers encoder batch needs with inspect.signature; code comments mark this as a refactor candidate.
  • Potential null risk: trainer file-handler setup references validator/tester loggers even though validation/testing sections may be optional.
  • Dtype contract needs confirmation: loader factory defaults integer type to torch.int32, while ExampleDataset defaults to torch.int64.
  • Julia produce_data requires at least two distributed workers and worker-visible make_data; seed-per-datapoint logic supports determinism.
  • Zarr is the cross-language contract, but schema/field names are implicit in writer/reader functions. Changing Julia saved keys requires coordinated Python reader/preprocessing and tests.
  • Julia depends on external CausalSets from Codeberg main; reproducibility may depend on Manifest pinning.
