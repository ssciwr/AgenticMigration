Example Repository Overview

New-contributor map for a two-package research monorepo: Example.jl generates causal-set data into Zarr archives; ExamplePy reads Zarr data and trains, evaluates, and tunes graph neural networks.

Class, struct, and important free-function descriptions

Python core

  • Configurable (ExamplePy/src/Example/base.py): common from_config construction contract.
  • PyObjectTag, ConfigHandler (config_utils.py): YAML tags !pyobject, !sweep, !coupled-sweep, !range, !random_uniform, and !reference.
  • Config free functions (config_utils.py): get_loader and constructors wire YAML files into Python objects and expanded training configs.
  • ModuleWrapper, GNNModel (gnn_model.py): central configurable model shell with encoder, pooling-or-latent path, graph-feature branch, and task heads.
  • Snapshot, Trainer (train.py): checkpoint serialization and full train/validate/test loop.
  • TrainerDDP plus DDP free functions (train_ddp.py): process-group setup/cleanup and distributed training wrapper.
  • ExampleTune free functions (ExampleTune/tune.py): load configs, build Optuna search spaces, create studies, and save best configs.

Python model/data/evaluation

  • GNNBlock: PyG GNN layer stack with normalization, activation, dropout, and skip options.
  • SkipConnection, Sequential, LinearSequential: residual, structured sequence, and MLP helpers.
  • GPSModel, GPSTransformer, RedrawProjection: graph transformer/GPS components.
  • ExampleDatasetBase, ExampleDataset: Zarr-backed PyTorch Geometric dataset with lazy or processed reads.
  • DataLoaderFactory, DistributedDataLoaderFactory: shared/per-stage data configs, splits, loaders, and samplers.
  • Evaluator, Validator, Tester, DefaultEarlyStopping: metrics, reports, and stopping policy.

Julia structs and free functions

  • CsetFactory (cset_factories.jl): validates top-level generation config and dispatches by cset type string.
  • PolynomialCsetMaker, LayeredCsetMaker, RandomCsetMaker, DestroyedCsetMaker, GridCsetMakerPolynomial, MergedCsetMaker, ComplexTopCsetMaker: callable generator makers backed by JSON schemas.
  • FlipParamDeterminer: random-causet connectivity helper.
  • BranchedManifoldCauset: custom causet over branched manifolds, convertible to CausalSets.BitArrayCauset.
  • Generation free functions: make_polynomial_manifold_cset, layered/random/grid/merge/destroy helpers create causets and metadata.
  • Graph free functions: make_adj, max_pathlen, transitive_reduction! prepare graph features.
  • Production/save free functions: setup_config, prepare_dataproduction, setup_multiprocessing, produce_data, default_chunks, and dict_to_zarr drive distributed Zarr output.

Module descriptions and relationships

ExamplePy/src/Example/

  • base.py: config-construction ABC.
  • config_utils.py, utils.py: YAML loader extension, sweeps, references, imports, nested path helpers, seeding.
  • gnn_model.py, models/*: central model composition and reusable neural building blocks.
  • dataset_base.py, dataset_ondisk.py, load_zarr.py: Zarr access and PyG data conversion.
  • dataloaders.py: train/validation/test split modes and PyG/distributed loader creation.
  • evaluate.py, early_stopping.py: metrics, validation/test reports, early stopping from DataFrame columns.
  • train.py, train_ddp.py: normal and DDP training orchestration.
  • ExampleTune/tune.py: Optuna study creation, suggestion conversion, and best-config saving.

Example.jl/src/

  • Example.jl: central include/export file.
  • utils.jl: config validation and pseudo-sprinkling helpers.
  • csetgeneration*.jl, layeredgeneration.jl, branchedcsetgeneration.jl, grid_like_causets.jl: causal-set construction families.
  • csetmerging.jl, destroy_manifold_like_cset.jl: combine or perturb causal sets.
  • curvature_on_manifold.jl, graph_utils.jl: geometric/graph feature helpers.
  • cset_factories.jl: schema-validated config-to-maker layer.
  • preparation.jl: config merge, provenance/source copying, multiprocessing, production setup.
  • save_data.jl: recursive dictionary-to-Zarr writer.

Starting points and entry paths

Start here

  1. Read AGENTS.md for repository rules and architecture preferences.
  2. Read Example.jl/examples/produce_data.jl for end-to-end data generation.
  3. Read ExamplePy/configs/train_classifier.yaml for an end-to-end training config.
  4. For Python internals: train.py → gnn_model.py → dataloaders.py.
  5. For the data contract: save_data.jl + dataset_ondisk.py + ExamplePy/test/conftest.py.
  6. For Julia generation: cset_factories.jl around CsetFactory, then follow selected maker modules.

Generate data

  1. CLI: Example.jl/examples/produce_data.jl.
  2. Define make_cset_data(worker_factory)::Dict.
  3. Call produce_data(chunksize, configpath, make_cset_data).
  4. setup_config and CsetFactory validate config and prepare maker structs.
  5. Workers generate dictionaries; writer persists numbered groups through dict_to_zarr.

Train/evaluate

  1. Load YAML using yaml.load(..., Loader=Example.get_loader()).
  2. Optionally expand with ConfigHandler(config).run_configs.
  3. Build loaders with DataLoaderFactory.from_config(...).prepare_dataloaders().
  4. Build trainer with Trainer.from_config(...).
  5. Run run_training(train_loader, val_loader) and run_test(test_loader).
  6. Resume with Trainer.load_checkpoint(path) or Snapshot.load(path).

How to run tests and tools

Python

  • Install: cd ExamplePy && pip install -r requirements-cpu.txt && pip install -e .[dev,docs] (or hardware-specific requirements file).
  • Tests: cd ExamplePy && pytest.
  • CI coverage command: pytest test --cov=./src/Example --cov-report=xml.
  • Lint/format: cd ExamplePy && ruff format src/ && ruff check src/.
  • Docs: cd ExamplePy && mkdocs serve.

Julia

  • Tests: julia --project=Example.jl -e "using Pkg; Pkg.test()".
  • REPL alternative: using TestItemRunner; @run_package_tests.
  • Docs: cd Example.jl/docs && julia --color=yes --project make.jl.
  • Data example: julia --project=Example.jl Example.jl/examples/produce_data.jl --config Example.jl/examples/example_config.yaml --num_workers 2 --chunksize 1.

CI and pre-commit

  • .github/workflows/ci.yml: Julia tests on Ubuntu/Windows/macOS for Julia 1.11.1 and 1; Python tests on Ubuntu for Python 3.12 and 3.13.
  • .github/workflows/docs.yml: deploys Python MkDocs and Julia Documenter docs.
  • .pre-commit-config.yaml: julia-format, ruff-format, ruff-check --fix, nbstripout, line endings, large-file, merge-conflict, TOML checks.
  • Run all hooks: pre-commit run --all-files.

Constraints, risks, and open questions

  • Zarr is the cross-language contract; schema changes must update Julia writers, Python readers, fixtures, and docs together.
  • !pyobject requires full import paths; saved configs must preserve reloadable tags.
  • Some Python schemas allow additionalProperties: true; check behavior before relying on strict validation.
  • GNNModel forbids simultaneous latent and pooling paths, and graph-feature processing requires both net and aggregation callable.
  • Trainer/evaluator signatures must match model outputs and PyG data objects; examples often use custom callables, so YAML importability matters.
  • DDP defaults such as nccl are not CPU/Windows-friendly unless adjusted.
  • Julia produce_data requires at least two worker processes and warns that too-small chunks can deadlock.
  • Julia provenance helpers call git/Pkg dependency APIs; production/test environments need dependency metadata available.
  • CausalSets is sourced from Codeberg main despite compat pinning, so reproducibility depends on manifest locking and source availability.
  • Some stochastic/geometric generation paths are complex; tests cover many edges, but performance and retry behavior should be monitored for large datasets.
